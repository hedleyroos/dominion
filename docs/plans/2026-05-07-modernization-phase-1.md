# Modernisation Phase 1

**Date:** 2026-05-07  
**Status:** ✅ Completed (verified 2026-07). All items below are implemented; note the repo
was later restructured so `app/src/dominion/` paths are now `dominion/` (settings/celery/
asgi/wsgi under `dominion/conf/`). Django is now 6.0. This doc is historical — do not treat
as an active requirement.

## Motivation

The pipelines-core project was added to the workspace as the reference for modern habits. This plan brings Dominion into alignment on seven fronts raised by the team.

## Scope

1. **`requirements.in`** — switch from a flat pinned `requirements.txt` to `requirements.in` compiled with pip-compile. Top-level intent is declared in `.in`; pinned hashes live in the generated `.txt`.
2. **pytest** — replace `manage.py test` with pytest (pytest-django, pytest-asyncio, pytest-xdist). All test environments run in parallel via `-n auto`.
3. **Current Celery setting names** — the old-style uppercase env vars (`CELERY_ALWAYS_EAGER`) are removed from tox.ini; Celery 5.x uses `task_always_eager` in `app.conf` directly (already done) but the env var names in tox were stale.
4. **Django 5.2 LTS** — upgrade from 4.0.1 to 5.2 (LTS). Matches pipelines-core.
5. **Async later** — async view conversion is deferred. Groundwork only: fix the ASGI/WSGI settings module inconsistency, add `decorators.py` with an async-safe `django()` decorator, install pytest-asyncio.
6. **Parallel tests** — pytest-xdist with `-n auto` in every tox environment.
7. **Dockerfile** — multi-arch image (`python:3.12-slim`); runtime architecture detection via `uname -m`; gunicorn + gevent entrypoint. A `docker-compose.yaml` is included for local development (app + postgres + rabbitmq + redis).

## Decisions

| Topic | Decision | Rationale |
|-------|----------|-----------|
| Django version | 5.2 LTS (not 6.0) | Matches pipelines-core; 6.0 too new |
| Connexion + DRF | Keep both | Connexion owns the API; DRF owns serialization |
| `app/src/` path hack | Leave for later | Correct but out of scope |
| ASGI conversion | Groundwork only | Full async conversion is a separate phase |
| Architecture-split requirements | Not needed | No arch-specific binary wheels (no PyTorch) |

## What This Is Not

This plan does **not** cover:
- Converting views to async (separate phase)
- Fixing the `app/src/` sys.path hack (separate refactor)
- Moving Connexion 2 → Connexion 3 (separate task)
- Adding new features
